담보평가 사전체크 · Windows 실행 안내

1. 실행 순서
- Python 3.10 이상을 설치하고 PATH에 등록합니다.
- start_dashboard.bat를 더블클릭합니다. npm 설치는 필요 없습니다.
- http://127.0.0.1:8080 이 기본 브라우저에서 열립니다.
- 창을 닫거나 Ctrl+C로 서버를 종료합니다. 포트 8080은 비어 있어야 합니다.
- 이 프로젝트는 연결된 /workspace에 기존 담보평가 프로젝트가 없어 새로 생성한 독립 데모입니다.
- Windows .bat 실제 더블클릭은 Linux 검증 환경에서 수행하지 못했습니다.

2. 화면 구조
홈 → 사전체크(물건유형 / 공개정보 / 권리관계 / 결과) → 관련 사례·가이드 → 운영 대시보드.
사례검색, Rule 정보, 설정 메뉴를 제공합니다.
집합건물은 전체 1~9단계 중 3번의 조회 행동만 KB시세+공동주택가격으로 대체합니다.
토지는 토지이용계획, 건물은 토지이용계획+건축물대장을 확인합니다.
1~9단계 전체 자동화나 공개 사이트 자동조회 기능은 없습니다. FC가 조회 여부를 입력합니다.

3. Rule Engine
js/rules.js가 R001→R002→R003→R004~R006→R099 순서로 판단합니다.
결과는 진행 가능 / 보완 필요 / 법무팀 검토 필요 세 가지입니다.
선순위 채권 금액에는 임의 임계값을 적용하지 않습니다.
실제 Rule 교체 위치: data/rules.json(메타데이터), js/rules.js(조건).
출처 분류는 원문 기반 / 데모 가정 / 원문 기반 + 데모 가정입니다.
현재 원문 Excel 미제공으로 모든 Rule 출처는 데모 가정입니다.
원문과 승인된 실무 기준을 검증하기 전 실제 업무의 최종 판단에 사용하지 마세요.

4. BGE-M3 (선택)
BGE 없이 Rule·로그·대시보드·키워드 검색은 동작합니다.
API 주소: http://127.0.0.1:8000
GET /health가 {"ok":true}이면 의미 검색을 사용합니다.
POST /search 요청: {"query":"검색어","top_k":5}
응답: {"engine":"BGE-M3","results":[{"id":"문서ID","score":0.84,...}]}
호출 제한은 2.5초이며 오류 시 Local Keyword Search로 전환합니다.
검색 결과는 Rule 결과를 결정하지 않습니다. 주소는 BGE에 보내지 않습니다.
선택적 서버 설치: py -3 -m pip install -r python_backend\requirements.txt
인터넷이 없는 회사 PC에서는 승인된 wheel 패키지 및 모델 폴더를 미리 준비해야 합니다.
BGE_MODEL_PATH 환경변수에 실제 로컬 BAAI/bge-m3 모델 폴더 경로를 지정합니다.
check_bge_cache.bat로 config.json 존재 여부를 확인합니다.
start_bge_offline.bat를 실행 후 /health에서 ok:true를 확인합니다.
서버는 HF_HUB_OFFLINE=1로 동작하며 모델을 자동 다운로드하지 않습니다.
현재 제공 환경에는 모델이 없으므로 BGE 미연결이며 semantic search 품질은 미검증입니다.
C003/C010/C014/C018/C015/K002 원문 문서가 없어 해당 ID 검색 순위도 검증하지 않았습니다.
기존 BGE API 사용 시 CORS에서 http://127.0.0.1:8080을 허용해야 합니다.
BGE 응답 문서는 id/score 및 title/content/kind/target_type/result/rule_id를 제공하면 필터가 동작합니다.

5. 개인정보 범위
주소는 마스킹 상태를 그대로 유지하고 브라우저 메모리에만 존재합니다.
주소 마스킹 복원, 실제 개인정보 생성, OCR, 주민번호 및 서류 업로드 기능은 없습니다.
선순위 금액도 로그에 저장하지 않습니다.
로그에는 timestamp/target_type/result/rule_id/rule_name/reason만 저장합니다.
reason은 Rule 조건 문자열이며 사용자 자유입력은 저장하지 않습니다.

6. Dashboard 로그
브라우저 localStorage 키: collateral.precheck.logs.v1
결과 확인 시 한 건을 저장합니다. 법무 저장 CTA는 같은 결과의 중복 저장을 방지합니다.
보완 후 재평가는 별도의 사전체크 기록이며 고유 물건 수가 아닙니다.
동일 브라우저·동일 주소에서 유지되며 브라우저 데이터 삭제 시 사라집니다.
설정에서 JSON 내보내기가 가능합니다. DB나 사용자 간 공유는 없습니다.
샘플 데이터 48건은 Sample Mode에만 표시되며 localStorage에 섞이지 않습니다.
실제 체크를 하면 실제 로그 화면으로 전환됩니다.
법무팀 이관율 = 법무팀 검토 필요 / 전체.
예상 사전 필터율 = 1 - 법무팀 이관율. 실제 업무 절감 성과가 아닌 데모 지표입니다.
집계 날짜는 한국시간입니다. 최근 10건 테이블과 최근 7일 추이를 표시합니다.

7. 사례 데이터
위치: data/docs.json. DEMO-* 문서는 요구사항을 설명하기 위한 합성 업무 예시입니다.
실제 판례, 실제 내부 사례 또는 원문 사례를 의미하지 않습니다.
실제 사례 파일 제공 시 검증 후 교체하세요. 검색어에 주소·개인정보를 입력하지 마세요.

8. 검증 / 빌드 (개발자 선택)
Node.js가 있는 경우 npm test, npm run build.
정적 배포 결과는 dist/에 생성됩니다. 앱 실행에는 Node.js가 필요 없습니다.
브라우저 테스트는 Python Playwright 및 Chromium이 있는 개발환경에서 tests/browser_test.py로 실행합니다.
검증 결과는 TEST_REPORT.txt를 참고하세요.
